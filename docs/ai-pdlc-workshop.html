L1 · why AI PDLC · 5 min

Fast code is not the bottleneck. Unasked questions are.

Before the code

A one-line feature card has ten unstated decisions. If nobody grills it, the agent guesses — confidently.

During the code

An agent will call itself done. Only a verifier it cannot edit, plus a human review, makes "done" mean something.

After the code

Shipping is not the end. The feature behaves differently in production, and someone — or something — has to watch it.

AI PDLC = agents carry the feature from board to production and keep watching; humans decide at three gates — story approval, PR review, release.

    L6 · plan agent · 6 min · grow the plan

    The plan agent breaks the story into verifiable tasks

    • Each task names the test that proves it — no test, no task.
    • Dependencies decide what can run in parallel (subagents).
    • Tasks are written back to ADO as children of the story.
    • Estimate is an agent guess; Squad Lead adjusts, doesn't approve.

    L9 · monitor after deploy · 8 min · simulate a day

    Deploy is not done. The monitor agent watches and files back to the board.

    Watched signals come from the story's NFRs and the release plan: export error rate, p95 latency, rows exported per user, cost per export.

    The agent files, it doesn't fix. Fixes go through the same journey, with the evidence attached.

    Systems of record

    State → the board · Text → git (OpenSpec change folder) · What happened → Temporal history + append-only review_events. The control plane refuses to act when they disagree.

    Three loops, three owners

    Lifecycle loop → Temporal (days, gates, restarts) · planning loop inside an agent → Embabel GOAP (one activity) · coding loop inside a task → omp session over ACP (one sandbox, heartbeats). Inner loops never touch board state. Per-agent pollers rejected; one idempotent reconciler only where webhooks are unreliable.

    Maker-checker = four things composed

    Durable wait for named signals on a version · separation of duties policy · line-anchored comments on rendered markdown · per-version signatures with content hash, mirrored to review.md.
